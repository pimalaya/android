# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Added multi-account contact management over CardDAV, JMAP for Contacts, Microsoft Graph and the Google People API, unified behind one client and a contact-first view that merges every account's addressbooks.
- Added mail and calendars beside the contacts, merged across accounts the same way: mailboxes over IMAP, JMAP, Microsoft Graph or the Gmail API in one message list, calendars over CalDAV, JMAP, Microsoft Graph or the Google Calendar API in one agenda. A JMAP account serves all three domains from its single session. A message row carries its subject, sender, mailbox and account, an avatar keyed by the sender's address, a paperclip leading it when it carries an attachment, and its replied and important marks; an agenda row carries the same shape, with the glyph of its component leading it, its calendar's initial in its calendar's own colour, and how far off it is where a message puts its date.
- Added a reader behind every message: a header card with the sender's avatar, the subject, the full date and how long ago it was, and one badge per attachment, over the message itself. HTML bodies render sandboxed, with scripting off, network loads blocked and images not loaded, so opening a message cannot report back to whoever sent it. Opening a message marks it read, and the card carries the three things a reader does next: mark it unread, mark it important, or delete it into the account's trash, which is the mailbox the server marks as such rather than one guessed from its name. An account that names none marks the message deleted where it is and says so, because an expunge would take every deleted message of that mailbox, including ones another client marked. All three are written to the store and pushed by the next sync, so they work with no network. A message is kept once opened, filed against its own row as the bytes the server sent, so opening it again is instant and works offline; a sync stores envelopes and never discards what a read stored.
- Added a composer: the sender, the recipients as removable chips, with the copies hidden until asked for, a subject and the text. Sending puts the message in the account's outbox, listed as a mailbox of its own, where it shows as waiting until a sync hands it to the account's sending server and files a copy in your sent mailbox, so a message can be written and sent with no network. A message the server refuses for good is kept and shown as refused, with what the server said, rather than being offered again on every sync; anything else, no network among them, leaves it waiting for the next one. Where an account sends is asked when it is connected: the recommended setup offers a *send mail* switch and picks the server itself, the advanced setup lists the SMTP servers your address publishes, implicit TLS or STARTTLS, and takes one you type, and an account's settings can set or change it afterwards, which is what an account connected before this could not do. Plain text, no attachments and no drafts yet, and a JMAP account is not offered as a sender: its submission is a different shape and is not written.
- Added a page behind every agenda row: the page a contact opens on, read and edited in the same place, with each row a dialog, an add button for the properties the entry has not got yet, and a save. The sections follow the component, since an event runs between two moments, a to-do is due and partly done, and a journal entry is written on a day. An edit patches the object through its syntax tree, so alarms, attendees and everything else the page does not manage survive untouched, and stages it against the ETag the entry was read at, which the next sync pushes it guarded by. The same page creates and deletes: the agenda's add button opens it on a new entry placed at the next whole hour, asking which calendar when there is more than one, and the bar's delete removes the entry after asking. Each push is guarded, a create on the resource not existing so a UID collision is refused rather than overwriting; all three are staged, so the agenda shows them at once and with no network. CalDAV and Microsoft Graph for now; a JMAP calendar says so rather than pretending to save.
- Added dates worded the way a reader would tell them, one vocabulary across the three domains: Today, Yesterday and 3 days ago in the message list, in 20 minutes and 2 hours ago in the agenda, the exact date with the distance beside it in an open message. Told in calendar days rather than elapsed hours, so a message from 23:00 last night reads Yesterday.
- Added one app bar across the three domains: the burger opens the accounts drawer, one button each switches to mail, contacts or calendars with the one being shown in the accent, then search on contacts and one overflow holding the filter and the domain's other actions. The app opens on the mail list, and every domain has an add button.
- Added offline-first storage across all three domains: one local store rendered instantly, and every action a write to it. Marking a message read, flagging one, deleting one, sending one, creating a calendar entry, editing one, deleting one and saving a contact all work with no network and go out on the next sync; only synchronizing and fetching a message body need one.
- Added incremental synchronization on every backend through io-pimdir's sync engine, with three-way-merge conflicts that auto-resolve clean divergences and surface only genuine same-field collisions for manual resolution. A sync pass opens one connection per account and does all its work on it, rather than one per request: marking three messages read and syncing is one IMAP session, not four, and a concurrent push uses one connection per worker rather than one per card. Every domain asks what changed rather than for everything: a calendar enumerates on a sync token and reads only the entries that moved, and a mailbox on its modseq where the server offers QRESYNC, so a refresh with nothing to report costs one round trip per collection instead of every body it holds. The drawer's sync runs contacts, then mail, then calendars, the dialog naming the domain it is on, and a mailbox the filter hides is not synced.
- Added two-way phone synchronization: each addressbook mirrors into its own Android account (the DAVx5 pattern), so edits from any contacts app converge into the store and ride upstream.
- Added scheduled background synchronization per addressbook (WorkManager), from every fifteen minutes to daily, reporting each pass in a notification.
- Added automatic setup from an email address or a bare domain: parallel provider-rule, PACC, CardDAV, CalDAV, autoconfig and JMAP discovery over a DNS-over-HTTPS resolver, then one screen offering the domains the address serves. An address hosted at Google or Microsoft, custom domains included, is offered mail, contacts and calendars from the provider's own rules. The recommended setup is a switch per domain and a password prompt, the app picking the servers and connecting only what a login and a password can reach; the advanced setup lists every discovered configuration and sign-in under each switch, manual server entry included. Finishing the setup synchronizes every domain the account covers before landing on the first of them.
- Added authentication by password, API token or OAuth 2.0 (IMAP and SMTP over SASL XOAUTH2), with shipped Google and Microsoft clients, custom clients, and zero-registration OAuth (metadata discovery, dynamic client registration and PKCE); credentials are encrypted in the Android Keystore.
- Added a full vCard 4.0 editor: a form covering every form-worthy property, an advanced per-property editor completing the RFC 6350 registries with structured-value fields, and a raw source editor.
- Added a two-axis filter over each list, by account and by collection, offering only the accounts the list on screen can hide. Deleting an account removes its mail and calendars with it, its contacts moving into the on-device book.
- Added a merged contact view with UID-based deduplication, manual link and unlink, a merge flow, a semi-automatic duplicate remover, search, vCard import and export, and a divergence flag opening a conflict-resolution form.
- Added lossless round-trips for Google People and Microsoft Graph: vCard lines with no native slot are stashed server-side and restored verbatim, and provider-only fields ride the vCard as read-only vendor properties.
- Added a next-birthday peek computed from the merged cards.
- Added a Google Play support prompt with one-time pay-what-you-want tiers; the FOSS builds ship free and ungated.
- Added the packaging: a Nix flake pinning the toolchain and a release workflow assembling one signed APK per ABI plus a universal one.
- Set the minimum supported Android version to 8.0 (API 26).
