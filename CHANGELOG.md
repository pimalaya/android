# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Added multi-account contact management over CardDAV, JMAP for Contacts, Microsoft Graph and the Google People API, unified behind one client and a contact-first view that merges every account's addressbooks.
- Added mail and calendars beside the contacts, merged across accounts the same way: mailboxes over IMAP, JMAP, Microsoft Graph or the Gmail API in one message list, calendars over CalDAV, JMAP, Microsoft Graph or the Google Calendar API in one agenda. A JMAP account serves all three domains from its single session. Each list opens on a large title over a count and groups its rows into rounded cards under a section header: messages by day, contacts by letter, entries by day. A message row carries an avatar keyed by the sender's address, the sender and the time, the replied mark and an unread dot, the subject ended by a star when important and a paperclip when it carries an attachment, and the mailbox and account; the mail list searches the sender and the subject, filters on unread and attachments, and a long press selects messages to mark read, star or delete together. Contacts and agenda rows share the message row's shape, each naming the collection and account it comes from; an agenda row carries its calendar's initial in the calendar's own colour, the entry ended by its start, then the kind of entry and how long it runs, under a week card whose days filter the agenda to themselves and whose arrows and week number move between weeks.
- Added a reader behind every message: the subject with its star, the mailbox it is filed in, a sender card with the avatar, the full date and how long ago it was, and one badge per attachment, over the message itself. HTML bodies render sandboxed, with scripting off, network loads blocked and images not loaded, so opening a message cannot report back to whoever sent it. Opening a message marks it read, and the reader answers it: reply to everyone on it, threaded under it and marking it answered, or forward its text. It also carries mark unread, mark important, and delete it into the account's trash, which is the mailbox the server marks as such rather than one guessed from its name. An account that names none marks the message deleted where it is and says so, because an expunge would take every deleted message of that mailbox, including ones another client marked. All three are written to the store and pushed by the next sync, so they work with no network. A message is kept once opened, filed against its own row as the bytes the server sent, so opening it again is instant and works offline; a sync stores envelopes and never discards what a read stored.
- Added a composer: one card of labelled rows for the sender, the recipients as removable chips in a tone that stands out from the card, with the copies hidden until asked for, a subject and the text. Sending puts the message in the account's outbox, listed as a mailbox of its own, where it shows as waiting until a sync hands it to the account's sending server and files a copy in your sent mailbox, so a message can be written and sent with no network. A message the server refuses for good is kept and shown as refused, with what the server said, rather than being offered again on every sync; anything else, no network among them, leaves it waiting for the next one. Where an account sends is asked when it is connected: the recommended setup offers a *send mail* switch and picks the server itself, the advanced setup lists the SMTP servers your address publishes, implicit TLS or STARTTLS, and takes one you type, and an account's settings can set or change it afterwards, which is what an account connected before this could not do. Plain text, no attachments and no drafts yet, and a JMAP account is not offered as a sender: its submission is a different shape and is not written.
- Added a page behind every agenda row: the page a contact opens on, read and edited in the same place, with each row a dialog, an add button for the properties the entry has not got yet, and a save. The sections follow the component, since an event runs between two moments, a to-do is due and partly done, and a journal entry is written on a day. An edit patches the object through its syntax tree, so alarms, attendees and everything else the page does not manage survive untouched, and stages it against the ETag the entry was read at, which the next sync pushes it guarded by. The same page creates and deletes: the agenda's add button opens it on a new entry placed at the next whole hour, asking which calendar when there is more than one, and the bar's delete removes the entry after asking. Each push is guarded, a create on the resource not existing so a UID collision is refused rather than overwriting; all three are staged, so the agenda shows them at once and with no network. CalDAV and Microsoft Graph for now; a JMAP calendar says so rather than pretending to save.
- Added dates worded the way a reader would tell them, one vocabulary across the three domains: Today, Yesterday and 3 days ago heading the message list's days, in 20 minutes and 2 hours ago on an agenda entry's page, the exact date with the distance beside it in an open message. Told in calendar days rather than elapsed hours, so a message from 23:00 last night reads Yesterday.
- Added a bottom bar switching between mail, contacts and calendars, mail carrying its unread count, and one app bar across them: the burger opens the drawer, one card per account saying whether it is deactivated or when it last synced, over actions fixed at the bottom, and the bar takes the domain's name once its large title scrolls away, then on contacts birthdays, duplicates and import/export, and on every list the filter. The app opens on the mail list, and every domain has an extended add button that shrinks to its glyph while the list scrolls.
- Added offline-first storage across all three domains: one local store rendered instantly, and every action a write to it. Marking a message read, flagging one, deleting one, sending one, creating a calendar entry, editing one, deleting one and saving a contact all work with no network and go out on the next sync; only synchronizing and fetching a message body need one.
- Added incremental synchronization on every backend through io-pimdir's sync engine, with three-way-merge conflicts that auto-resolve clean divergences and surface only genuine same-field collisions for manual resolution. A sync pass opens one connection per account and does all its work on it, rather than one per request: marking three messages read and syncing is one IMAP session, not four, and a concurrent push uses one connection per worker rather than one per card. Every domain asks what changed rather than for everything: a calendar enumerates on a sync token and reads only the entries that moved, and a mailbox on its modseq where the server offers QRESYNC, so a refresh with nothing to report costs one round trip per collection instead of every body it holds. The drawer's sync runs contacts, then mail, then calendars, the dialog naming the domain it is on, over every account; pulling a list down syncs that domain alone, within what the filter shows. A server that throttles is waited on for as long as it asks, within a bound so a sync never hangs, and Gmail is read below its quota rather than at it.
- Added whole mailboxes: every message of every mailbox is listed, newest first, its sender, subject, date and marks stored in the same pass with no body, a page at a time, so the newest mail shows within seconds while the rest fills in and a sync cut off resumes where it stopped. The mail list loads lazily around where you scroll, so a mailbox of a hundred thousand messages scrolls to its oldest, and search, the unread and attachments chips, select-all and the unread badge cover every stored message, offline included. An account's settings bound its mail to the last 1, 3, 6, 12 or 24 months, by the date each message was sent; narrowing the bound frees what falls below it on the phone and nothing on the server, widening it brings the older mail back on the next sync. The paperclip is read from the message's type while listing, and corrected from its parts when you open it.
- Added a short first sync: after connecting an account, the mail tab waits only for the 50 newest messages of each mailbox, the inbox first, every pass taking the inbox first after it. Older mail fills in behind, 500 messages at a time, while the app is open on an unmetered network, and scrolling to the end of the list loads the next 50 of the mailboxes it is waiting on, or says older mail needs the network.
- Added band-by-band loading on Microsoft 365: older mail and the end of the list fetch only the messages they lack rather than every message already stored, changes made elsewhere reach the phone whatever the age of the message, and the first sync after connecting still waits only for the newest messages.
- Added two-way phone synchronization: each addressbook mirrors into its own Android account (the DAVx5 pattern), so edits from any contacts app converge into the store and ride upstream.
- Added scheduled background synchronization per addressbook (WorkManager), from every fifteen minutes to daily, reporting each pass in a notification.
- Added automatic setup from an email address or a bare domain: parallel provider-rule, PACC, CardDAV, CalDAV, autoconfig and JMAP discovery over a DNS-over-HTTPS resolver, then one screen offering the domains the address serves. An address hosted at Google or Microsoft, custom domains included, is offered mail, contacts and calendars from the provider's own rules. The recommended setup is a switch per domain and a password prompt, the app picking the servers and connecting only what a login and a password can reach; the advanced setup lists every discovered configuration and sign-in under each switch, manual server entry included. Finishing the setup lands on the first domain the account covers, mail first, and each domain syncs behind its dialog the first time its tab is opened.
- Added authentication by password, API token or OAuth 2.0 (IMAP and SMTP over SASL XOAUTH2), with shipped Google and Microsoft clients, custom clients, and zero-registration OAuth (metadata discovery, dynamic client registration and PKCE); credentials are encrypted in the Android Keystore.
- Added a full vCard 4.0 editor: a form covering every form-worthy property, an advanced per-property editor completing the RFC 6350 registries with structured-value fields, and a raw source editor.
- Added a two-axis filter over each list, by account and by collection, offering only the accounts the list on screen can hide. Deleting an account removes its mail and calendars with it, its contacts moving into the on-device book.
- Added a merged contact view with UID-based deduplication, manual link and unlink, a merge flow, a semi-automatic duplicate remover, search, vCard import and export, and a divergence flag opening a conflict-resolution form.
- Added lossless round-trips for Google People and Microsoft Graph: vCard lines with no native slot are stashed server-side and restored verbatim, and provider-only fields ride the vCard as read-only vendor properties.
- Added a next-birthday peek computed from the merged cards.
- Added a Google Play support prompt with one-time pay-what-you-want tiers; the FOSS builds ship free and ungated.
- Added the packaging: a Nix flake pinning the toolchain and a release workflow assembling one signed APK per ABI plus a universal one.
- Set the minimum supported Android version to 8.0 (API 26).
