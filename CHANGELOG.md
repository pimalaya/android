# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Added multi-account contact management over CardDAV, JMAP for Contacts, Microsoft Graph and the Google People API, unified behind one client and a contact-first view that merges every account's addressbooks.
- Added mail and calendars beside the contacts, merged across accounts the same way: mailboxes over IMAP or JMAP in one message list, calendars over CalDAV or JMAP in one agenda. A JMAP account serves all three domains from its single session. A message row carries its subject, sender, mailbox and account, an avatar keyed by the sender's address, a paperclip leading it when it carries an attachment, and its replied and important marks; an agenda row carries the same shape, with the glyph of its component leading it, its calendar's initial in its calendar's own colour, and how far off it is where a message puts its date.
- Added a reader behind every message: a header card with the sender's avatar, the subject, the full date and how long ago it was, and one badge per attachment, over the message itself. HTML bodies render sandboxed, with scripting off, network loads blocked and images not loaded, so opening a message cannot report back to whoever sent it. Opening a message marks it read, and the card carries the three things a reader does next: mark it unread, mark it important, or delete it into the account's trash, which is the mailbox the server marks as such rather than one guessed from its name. An account that names none marks the message deleted where it is and says so, because an expunge would take every deleted message of that mailbox, including ones another client marked. All three are written to the store and pushed by the next sync, so they work with no network. A message is kept once opened, filed against its own row as the bytes the server sent, so opening it again is instant and works offline; a sync stores envelopes and never discards what a read stored.
- Added a composer: the sender, the recipients with the copies hidden until asked for, a subject and the text. Sending puts the message in the account's outbox, where it shows as pending until a sync hands it to the account's SMTP server and files a copy in your sent mailbox, so a message can be written and sent with no network; one the server refuses stays in the outbox rather than being lost. The submission server is discovered when the account is connected, beside the one it reads from. Plain text, no attachments and no drafts yet, and a JMAP account is not offered as a sender: its submission is a different shape and is not written.
- Added a page behind every agenda row: the page a contact opens on, read and edited in the same place, with each row a dialog, an add button for the properties the entry has not got yet, and a save. The sections follow the component, since an event runs between two moments, a to-do is due and partly done, and a journal entry is written on a day. An edit patches the object through its syntax tree, so alarms, attendees and everything else the page does not manage survive untouched, and stages it against the ETag the entry was read at, which the next sync pushes it guarded by. The same page creates and deletes: the agenda's add button opens it on a new entry placed at the next whole hour, asking which calendar when there is more than one, and the bar's delete removes the entry after asking. Each push is guarded, a create on the resource not existing so a UID collision is refused rather than overwriting; all three are staged, so the agenda shows them at once and with no network. CalDAV only for now; a JMAP calendar says so rather than pretending to save.
- Added dates worded the way a reader would tell them, one vocabulary across the three domains: Today, Yesterday and 3 days ago in the message list, in 20 minutes and 2 hours ago in the agenda, the exact date with the distance beside it in an open message. Told in calendar days rather than elapsed hours, so a message from 23:00 last night reads Yesterday.
- Fixed: an account signed in with OAuth stopped syncing until it was added again. Two faults, both on the token refresh. A JMAP server's first call reported its 401 in a shape the app did not recognise as one, so the refresh was never attempted; and each domain kept its own copy of the sign-in, so with a provider that issues a new refresh token every time (Fastmail among them), refreshing contacts retired the copies mail and calendars were holding. A sign-in is now stored once and named by every domain it covers, so renewing it renews all of them and there is no second copy to fall behind. Accounts stored by an earlier version are dropped on upgrade and have to be added again, once.
- Fixed: a message list showed the raw encoded words of a subject or a sender name written in anything but ASCII, where the reader below it showed the words. An IMAP envelope is header text rather than parsed headers, so it is decoded before the store holds it.
- Fixed: a message whose attachment carried no `Content-Disposition` showed no paperclip. A part naming a file counts as an attachment now, which is how plenty of mail in the wild is written; a part the sender marked inline still does not.
- Added one app bar across the three domains: the burger opens the accounts drawer, one button each switches to mail, contacts or calendars with the one being shown in the accent, and that domain's actions follow. The app opens on the mail list, and every domain has an add button.
- Added offline-first storage across all three domains: one local store rendered instantly, and every action a write to it. Marking a message read, flagging one, deleting one, sending one, creating a calendar entry, editing one, deleting one and saving a contact all work with no network and go out on the next sync; only synchronizing and fetching a message body need one.
- Added incremental synchronization on every backend through io-pimdir's sync engine, with three-way-merge conflicts that auto-resolve clean divergences and surface only genuine same-field collisions for manual resolution.
- Added two-way phone synchronization: each addressbook mirrors into its own Android account (the DAVx5 pattern), so edits from any contacts app converge into the store and ride upstream.
- Added scheduled background synchronization per addressbook (WorkManager), from every fifteen minutes to daily, reporting each pass in a notification.
- Added automatic setup from an email address or a bare domain: parallel provider-rule (MX), PACC, CardDAV, IMAP and JMAP discovery over a DNS-over-HTTPS resolver, then one screen offering the domains the address serves. The recommended setup is a switch per domain and a password prompt, the app picking the servers and connecting only what a login and a password can reach; the advanced setup lists every discovered configuration and sign-in under each switch, manual server entry included. Finishing the setup synchronizes every domain the account covers before landing on the first of them.
- Added authentication by password, API token or OAuth 2.0, with shipped Google and Microsoft clients, custom clients, and zero-registration OAuth (metadata discovery, dynamic client registration and PKCE); credentials are encrypted in the Android Keystore.
- Added a full vCard 4.0 editor: a form covering every form-worthy property, an advanced per-property editor completing the RFC 6350 registries with structured-value fields, and a raw source editor.
- Added a merged contact view with UID-based deduplication, manual link and unlink, a merge flow, a semi-automatic duplicate remover, search, vCard import and export, and a divergence flag opening a conflict-resolution form.
- Added lossless round-trips for Google People and Microsoft Graph: vCard lines with no native slot are stashed server-side and restored verbatim, and provider-only fields ride the vCard as read-only vendor properties.
- Added a next-birthday peek computed from the merged cards.
- Added a Google Play support prompt with one-time pay-what-you-want tiers; the FOSS builds ship free and ungated.
- Added the packaging: a Nix flake pinning the toolchain and a release workflow assembling one signed APK per ABI plus a universal one.
- Set the minimum supported Android version to 8.0 (API 26).
