# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Added multi-account contact management over CardDAV, JMAP for Contacts, Microsoft Graph and the Google People API, unified behind one client and a contact-first view that merges every account's addressbooks.
- Added mail and calendars beside the contacts, merged across accounts the same way: mailboxes over IMAP, JMAP, Microsoft Graph or the Gmail API in one message list, calendars over CalDAV, JMAP, Microsoft Graph or the Google Calendar API in one agenda. A JMAP account serves all three domains from its single session. Each list opens on a large title over a count and groups its rows into rounded cards under a section header: messages by day, contacts by letter, entries by day. A message row carries an avatar keyed by the sender's address, the sender and the time, the replied mark and an unread dot, the subject ended by a star when important and a paperclip when it carries an attachment, and the mailbox and account; the mail list searches the sender and the subject, filters on unread and attachments, and a long press selects messages to mark read, star or delete together. Contacts and agenda rows share the message row's shape, each naming the collection and account it comes from; an agenda row carries its calendar's initial in the calendar's own colour, the entry ended by its start, then the kind of entry and how long it runs, under a week card whose days filter the agenda to themselves and whose arrows and week number move between weeks.
- Added a reader behind every message: the subject with its star, the mailbox it is filed in, a sender card with the avatar, the full date and how long ago it was, and one badge per attachment, over the message itself. HTML bodies render sandboxed, with scripting off, network loads blocked and images not loaded, so opening a message cannot report back to whoever sent it. Opening a message marks it read, and the reader answers it: reply to everyone on it, threaded under it and marking it answered, or forward its text. It also carries mark unread, mark important, and delete. Deleting moves the message into the account's trash at once, the mailbox the server marks as such rather than one guessed from its name, and deleting it from the trash removes it for good. An account that names no trash, or an IMAP server that cannot expunge one message alone (no UIDPLUS), marks the message deleted where it is and the row says so, because an expunge would take every deleted message of that mailbox, including ones another client marked. All three are written to the store and pushed by the next sync, so they work with no network. A message is kept once opened, filed against its own row as the bytes the server sent, so opening it again is instant and works offline; a sync stores envelopes and never discards what a read stored.
- Added a composer: one card of labelled rows for the sender, the recipients as removable chips in a tone that stands out from the card, with the copies hidden until asked for, a subject and the text. Sending puts the message in the account's outbox, listed as a mailbox of its own, where it shows as waiting until a sync hands it to the account's sending server, so a message can be written and sent with no network. Its copy shows in your sent mailbox at once, filed by the sync once the message went, or recognised where Gmail or Microsoft 365 file their own, by its Message-ID or the one Gmail stamps on it; deleting the waiting message withdraws both. A message the server refuses for good is kept and shown as refused, with what the server said, rather than being offered again on every sync; anything else, no network among them, leaves it waiting for the next one. Where an account sends is asked when it is connected: the recommended setup offers a *send mail* switch and picks the server itself, the advanced setup lists the SMTP servers your address publishes, implicit TLS or STARTTLS, and takes one you type, and an account's settings can set or change it afterwards, which is what an account connected before this could not do. Plain text, no attachments and no drafts yet, and a JMAP account is not offered as a sender: its submission is a different shape and is not written.
- Added a page behind every agenda row: the page a contact opens on, read and edited in the same place, with each row a dialog, an add button for the properties the entry has not got yet, and a save. The sections follow the component, since an event runs between two moments, a to-do is due and partly done, and a journal entry is written on a day. An edit patches the object through its syntax tree, so alarms, attendees and everything else the page does not manage survive untouched, and stages it against the ETag the entry was read at, which the next sync pushes it guarded by. The same page creates and deletes: the agenda's add button opens it on a new entry placed at the next whole hour, asking which calendar when there is more than one, and the bar's delete removes the entry after asking. Each push is guarded, a create on the resource not existing so a UID collision is refused rather than overwriting; all three are staged, so the agenda shows them at once and with no network. CalDAV and Microsoft Graph for now; a JMAP calendar says so rather than pretending to save.
- Added dates worded the way a reader would tell them, one vocabulary across the three domains: Today, Yesterday and 3 days ago heading the message list's days, in 20 minutes and 2 hours ago on an agenda entry's page, the exact date with the distance beside it in an open message. Told in calendar days rather than elapsed hours, so a message from 23:00 last night reads Yesterday.
- Added a bottom bar switching between mail, contacts and calendars, mail carrying its unread count, and one app bar across them: the burger opens the drawer, one card per account saying when it last synced, or that it is deactivated, over actions fixed at the bottom, and the bar takes the domain's name once its large title scrolls away, then on contacts birthdays, duplicates and import/export, and on every list the filter. The app opens on the mail list, and every domain has an extended add button that shrinks to its glyph while the list scrolls.
- Added offline-first storage across all three domains: one local store rendered instantly, and every action a write to it. Marking a message read, flagging one, deleting one, sending one, creating a calendar entry, editing one, deleting one and saving a contact all work with no network and go out on the next sync; only synchronizing and fetching a message body need one. Each action shows at once in every list it concerns, a deleted message in the trash and a sent one in Sent, and a row carries a mark while its change waits for a sync, or once the server refused it for good.
- Added incremental synchronization on every backend through io-pimdir's sync engine, with three-way-merge conflicts that auto-resolve clean divergences and surface only genuine same-field collisions for manual resolution. A sync pass opens one connection per account and does all its work on it, rather than one per request: marking three messages read and syncing is one IMAP session, not four, and a concurrent push uses one connection per worker rather than one per card. Every domain asks what changed rather than for everything: a calendar enumerates on a sync token and reads only the entries that moved, and a mailbox on its modseq where the server offers QRESYNC, so a refresh with nothing to report costs one round trip per collection instead of every body it holds. The drawer's sync runs contacts, then mail, then calendars, over every account, a strip under each list's title naming the account and the domain over one progress bar spanning the whole sync, the app usable meanwhile and no report popping up once it ends; pulling a list down syncs that domain alone, within what the filter shows. A server that throttles is waited on for as long as it asks, within a bound so a sync never hangs, and Gmail is read below its quota rather than at it. Syncing is manual for now: there is no background sync.
- Added whole mailboxes: every message of every mailbox is listed, newest first, its sender, subject, date and marks stored in the same pass with no body, a page at a time, so the newest mail shows within seconds while the rest fills in and a sync cut off resumes where it stopped. The mail list loads lazily around where you scroll, so a mailbox of a hundred thousand messages scrolls to its oldest, and search covers every stored message, offline included. An account's settings bound its mail to the last 1, 3, 6, 12 or 24 months, by the date each message was sent; narrowing the bound frees what falls below it on the phone and nothing on the server, widening it brings the older mail back on the next sync. The paperclip is read from the message's type while listing, and corrected from its parts when you open it.
- Added a short first sync: after connecting an account, the mail tab waits only for the 50 newest messages of each mailbox, the inbox first, every pass taking the inbox first after it. Older mail fills in behind, 500 messages at a time (100 on Gmail), while the app is open on an unmetered network, a download glyph pulsing beside the mail count meanwhile.
- Added parallel mail sync: an account's mailboxes are listed several at a time, each on its own connection (four for Microsoft 365 and JMAP, three for IMAP, two for Gmail), the inbox begun first, so the first sync, every refresh, a moved download window and the background fill no longer wait on one mailbox after another. One mailbox failing no longer stops the others.
- Added faster calendar sync: an account's calendars sync several at a time, each on its own connection, and their events are read in a handful of requests rather than one each: twenty to a request on Microsoft 365, and none at all on Google and JMAP, whose listing already carries them. A calendar failing no longer stops the others, and an event deleted on Outlook while a sync reads it is left out rather than failing the sync.
- Added faster contact sync on Microsoft 365: contacts changed elsewhere (an import, a merge, many edited in Outlook) are read twenty to a request rather than one each, and a contact deleted on Outlook while a sync reads it is left out rather than failing the sync.
- Added band-by-band loading on Microsoft 365: older mail and a moved download window fetch only the messages they lack rather than every message already stored, changes made elsewhere reach the phone whatever the age of the message, and the first sync after connecting still waits only for the newest messages.
- Added two-way phone synchronization: each addressbook mirrors into its own Android account (the DAVx5 pattern), so edits from any contacts app converge into the store and ride upstream. It is off until turned on, in the setup or an addressbook's settings, and the contacts permission is asked only then.
- Added automatic setup from an email address or a bare domain: parallel provider-rule, PACC, CardDAV, CalDAV, autoconfig and JMAP discovery over a DNS-over-HTTPS resolver, then one screen offering the domains the address serves. An address hosted at Google or Microsoft, custom domains included, is offered mail, contacts and calendars from the provider's own rules. The recommended setup is a tick per domain, none ticked to begin with, the app picking the servers and the sign-in: Google's and Microsoft's own APIs through the app's sign-in for addresses they host, elsewhere JMAP before IMAP and the DAVs, and OAuth before an API token before a password; the advanced setup lists every discovered configuration and sign-in under each switch, manual server entry included. Finishing the setup lands on the first domain the account covers, mail first, and each domain syncs under its list's strip the first time its tab is opened.
- Added authentication by password, API token or OAuth 2.0 (IMAP and SMTP over SASL XOAUTH2), with shipped Google and Microsoft clients, custom clients, and zero-registration OAuth (metadata discovery, dynamic client registration and PKCE); credentials are encrypted in the Android Keystore.
- Added a full vCard 4.0 editor: a form covering every form-worthy property, an advanced per-property editor completing the RFC 6350 registries with structured-value fields, and a raw source editor.
- Added a filter page per list: each account with a checkbox, ticked, partly ticked or not, and its collections below it with theirs, kept across restarts; unticking an account folds its collections away, each keeping its own tick for when the account comes back, so two accounts' mailboxes of one name are told apart. A mailbox the server marks as the inbox, sent mail, drafts, trash, junk or archive goes by that name in your language rather than the server's own, such as Gmail's SENT or IMAP's INBOX. Mail offers role chips, Inbox, Sent, Drafts, Trash, Junk and Archive, each showing that mailbox of every shown account merged; contacts and calendars offer a Default chip. An account's settings switch it on and off: one that is off syncs nothing and leaves every list and filter, its data kept. Deleting an account removes its mail and calendars with it, its contacts moving into the on-device book.
- Added Deleted items, from the drawer: every deleted message, contact and entry the phone still keeps, in one list. One whose body is stored can be restored into a collection you pick, its last one preselected, and is uploaded by the next sync; mail restores on IMAP accounts for now. Free space shows what the kept items weigh, on its button too, and removes them for good; items waiting for the server stay. Deleting messages for good warns how many of them are not on the phone and so cannot be restored, opening them or downloading the trash keeping them restorable.
- Added a download window per account: the mail list shows the messages on the phone, whole with their attachments, since a date set by the first sync (as far back as the inbox's 50 newest messages), nothing asked at setup. A footer under the last one loads a month further back, saying how many messages and how many megabytes that is, or since a date of your choice, all your mail included, widening the sync period when it has to; an account's settings move it back the same way, or later, which frees the bodies below it after asking, their headers kept so search still finds them. The bodies download after each sync while the app is open, newest first, in every mailbox but the junk and the trash, before older headers keep filling in for search; on mobile data only those up to 256 KB, the larger ones waiting for Wi-Fi. A row not on the phone yet is dimmed, saying *Downloads on Wi-Fi* when that is what it waits for, and a search result beyond the window says *Not downloaded* and downloads when opened; opened offline, a message not on the phone says so. The unread badge counts the windows, the drawer counts the bodies left, and new-mail notifications never reach below the window. A mailbox's Download on the filter page keeps that one mailbox whole, trash included, and Stop returns it.
- Added attachments you can open and keep: tapping one in the reader opens it in the app your phone picks for it, or saves it into a folder on the phone, created on the spot if needed. A saved file is stored once however many messages carry it, and an attachment stays listed when its message is no longer on the phone, opening it then downloading the message first.
- Added a Files tab beside mail, contacts and calendars: your folders on the phone and every attachment of every account, searchable by name and sender and narrowed to images, PDFs or documents. A file opens, shares, saves into a folder, exports to the phone's storage or leads back to the message it came from; folders are created, renamed, deleted and filled from the phone's storage. Its filter page lists each account's attachments apart from your folders.
- Added links between items: every message, contact, calendar entry and file lists what it is linked to and why (an attachment, or linked by you), each opening the other. Link to searches your messages, contacts, entries and files for something to link, and Unlink removes one, warning when an automatic link may come back.
- Added automatic links: a message is linked to its sender's contact and to the event it invites to, whichever arrives first, a contact added later gathering the mail it sent, and existing mail is linked once after updating. Only real attachments are listed now, not inline images, and moving the download window later says how many messages and megabytes leave the phone.
- Added default collections: a new contact or event goes, without asking, to the collection the provider names default (JMAP, Microsoft 365, Google), else to the account's only writable one, else to the one set as default on the filter page; otherwise it asks, offering only the collections that take writes.
- Added a merged contact view with UID-based deduplication, manual link and unlink, a merge flow, a semi-automatic duplicate remover, search, vCard import and export, and a divergence flag opening a conflict-resolution form.
- Added lossless round-trips for Google People and Microsoft Graph: vCard lines with no native slot are stashed server-side and restored verbatim, and provider-only fields ride the vCard as read-only vendor properties.
- Added a next-birthday peek computed from the merged cards.
- Added the packaging: a Nix flake pinning the toolchain and a release workflow assembling one signed APK per ABI plus a universal one.
- Set the minimum supported Android version to 8.0 (API 26).

### Fixed

- Fixed a Gmail account's first sync stalling for a minute and a half, and later downloads pausing for a minute: two metadata requests sent side by side drew Gmail's "too many concurrent requests" refusals, each one waited out until the next minute with every other request held too. Such a refusal is now retried within a second or two, only a per-minute quota waits for the minute, and Gmail is read 25 messages to a request, one request of an account at a time, paced by Gmail's quota units per account, so a first sync lands in seconds. A first sync also stops reading once past the newest messages it needs rather than reading two more days of mail.
- Fixed opening a message waiting behind the background download of older mail or bodies: it now runs on its own, ahead of the download, and Gmail's background download steps are smaller.
- Fixed the sync strip naming the mail while nothing was counted yet: it now says *Starting the sync* until the bar can move, and its indeterminate bar is the same size as the counting one.
- Fixed every phone sync of an address book leaving a database connection open behind it: the whole app now shares one store.
- Fixed the app not working on Android 8 to 13: its store needs SQLite 3.37 or newer, which Android ships only from Android 14, so it could not be created on older phones. The app now bundles SQLite 3.49 and uses it on every Android version it supports, at the cost of about 1.9 MB per APK.
- Fixed the agenda listing everything from today on, months ahead, while it showed this week: with no day picked, this week now lists its own seven days, from the locale's first weekday, past days included, like every other week.
- Fixed a message with no date vanishing from the phone when older mail was loaded: a band of older mail is listed by date, which never returns an undated message, so its absence there no longer reads as a deletion.
- Fixed older mail never loading on Microsoft 365, Gmail and JMAP accounts, the end of the list saying it needed the network while the phone was online and the background fill stopping at once: the connection opened to load it did not know the mailboxes yet. The end of the list now says older mail needs the network only when there is none, and otherwise that it could not be loaded, with a tap to try again.
- Fixed the merged mail list slowing down as the store grew: a page over several mailboxes sorted every stored message of them before showing fifty, and now walks one index kept in that order, so a page of a fifty-thousand-message store reads in a fraction of a millisecond. An existing store gains the index the next time the app opens it.
