# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Added multi-account contact management over CardDAV, JMAP for Contacts, Microsoft Graph and the Google People API, unified behind one client and a contact-first view that merges every account's addressbooks.
- Added mail and calendars beside the contacts, merged across accounts the same way: mailboxes over IMAP, JMAP, Microsoft Graph or the Gmail API in one message list, calendars over CalDAV, JMAP, Microsoft Graph or the Google Calendar API in one agenda. A JMAP account serves all three domains from its single session. Each list opens on a large title over a count and groups its rows into rounded cards under a section header: messages by day, contacts by letter, entries by day. A message row carries an avatar keyed by the sender's address, the sender and the time, the replied mark and an unread dot, the subject ended by a star when important and a paperclip when it carries an attachment, and the mailbox and account; the mail list searches the sender and the subject, filters on unread and attachments, and a long press selects messages to mark read, star or delete together. Contacts and agenda rows share the message row's shape, each naming the collection and account it comes from; an agenda row carries its calendar's initial in the calendar's own colour, the entry ended by its start, then the kind of entry and how long it runs, under a week card whose days filter the agenda to themselves and whose arrows and week number move between weeks.
- Added a reader behind every message: the subject on two lines, the mailbox it is filed in, a sender card folded to the avatar, the sender and how long ago it was, unfolding to the recipients, the full date and its links, and one badge per attachment, over the message itself, which fits the width and zooms on a pinch. HTML bodies render sandboxed, with scripting off, network loads blocked and images not loaded, so opening a message cannot report back to whoever sent it. Opening a message marks it read, and the reader answers it: reply to everyone on it, threaded under it and marking it answered, or forward its text. Its bar carries delete, move, copy, the flags (read, important, answered), forward and reply, as icons: move and copy list the account's other mailboxes and are carried out on the server, a copy without uploading the message. Deleting moves the message into the account's trash at once, the mailbox the server marks as such rather than one guessed from its name, and deleting it from the trash removes it for good. An account that names no trash, or an IMAP server that cannot expunge one message alone (no UIDPLUS), marks the message deleted where it is and the row says so, because an expunge would take every deleted message of that mailbox, including ones another client marked. All three are written to the store and pushed by the next sync, so they work with no network. A message is kept once opened, filed against its own row as the bytes the server sent, so opening it again is instant and works offline; a sync stores envelopes and never discards what a read stored.
- Added a composer: one card of labelled rows for the sender, the recipients as removable chips in a tone that stands out from the card, with the copies hidden until asked for, a subject and the text. Sending puts the message in the account's outbox, listed as a mailbox of its own, where it shows as waiting until a sync hands it to the account's sending server, so a message can be written and sent with no network. Its copy shows in your sent mailbox at once, filed by the sync once the message went, or recognised where Gmail or Microsoft 365 file their own, by its Message-ID or the one Gmail stamps on it; deleting the waiting message withdraws both. A message the server refuses for good is kept and shown as refused, with what the server said, rather than being offered again on every sync; anything else, no network among them, leaves it waiting for the next one. Where an account sends is asked when it is connected: the recommended setup offers a *send mail* switch and picks the server itself, the advanced setup lists the SMTP servers your address publishes, implicit TLS or STARTTLS, and takes one you type, and an account's settings can set or change it afterwards, which is what an account connected before this could not do. A message is written in rich text or plain, the account's settings choosing how a new one starts and a reply following the message it answers: rich text shows as styled text, no syntax on screen, with a bar above the keyboard for bold, italic, strikethrough, code, links, lists and quotes, and a dash, a number or a `>` typed at a line's start starting a list or a quote; it is written out as Markdown. It goes out as HTML with the Markdown as its plain-text copy; HTML typed into it is sent as text, never as markup, and a message using no formatting goes out as its text alone. A rich reply or forward carries an HTML original as Markdown, its emphasis, links, lists and quotes kept and its own HTML never sent again. No attachments and no drafts yet, and a JMAP account is not offered as a sender: its submission is a different shape and is not written.
- Added a page behind every agenda row: the page a contact opens on, read and edited in the same place, with each row a dialog, an add button for the properties the entry has not got yet, and a save. The sections follow the component, since an event runs between two moments, a to-do is due and partly done, and a journal entry is written on a day. An edit patches the object through its syntax tree, so alarms, attendees and everything else the page does not manage survive untouched, and stages it against the ETag the entry was read at, which the next sync pushes it guarded by. The same page creates and deletes: the agenda's add button opens it on a new entry placed at the next whole hour, asking which calendar when there is more than one, and the bar's delete removes the entry after asking. Each push is guarded, a create on the resource not existing so a UID collision is refused rather than overwriting; all three are staged, so the agenda shows them at once and with no network. CalDAV and Microsoft Graph for now; a JMAP calendar says so rather than pretending to save.
- Added dates worded the way a reader would tell them, one vocabulary across the three domains: Today, Yesterday and 3 days ago heading the message list's days, in 20 minutes and 2 hours ago on an agenda entry's page, the exact date with the distance beside it in an open message. Told in calendar days rather than elapsed hours, so a message from 23:00 last night reads Yesterday.
- Added a bottom bar switching between mail, contacts and calendars, mail carrying its unread count, and one app bar across them: the burger opens the drawer, one card per account saying when it last synced, or that it is deactivated, over actions fixed at the bottom, and the bar takes the domain's name once its large title scrolls away, then on contacts birthdays, duplicates and import/export, and on every list the filter. The app opens on the mail list, and every domain has an extended add button that shrinks to its glyph while the list scrolls.
- Added offline-first storage across all three domains: one local store rendered instantly, and every action a write to it. Marking a message read, flagging one, deleting one, sending one, creating a calendar entry, editing one, deleting one and saving a contact all work with no network and go out on the next sync; only synchronizing and fetching a message body need one. Each action shows at once in every list it concerns, a deleted message in the trash and a sent one in Sent.
- Added incremental synchronization on every backend through io-pimdir's sync engine, with three-way-merge conflicts that auto-resolve clean divergences and surface only genuine same-field collisions for manual resolution. A sync pass opens one connection per account and does all its work on it, rather than one per request: marking three messages read and syncing is one IMAP session, not four, and a concurrent push uses one connection per worker rather than one per card. Every domain asks what changed rather than for everything: a calendar enumerates on a sync token and reads only the entries that moved, and a mailbox on its modseq where the server offers QRESYNC, so a refresh with nothing to report costs one round trip per collection instead of every body it holds. The drawer's sync runs contacts, then mail, then calendars, over every account, a dock above the bottom bar of each list, wherever it is scrolled, naming the account, the domain and what the sync is doing, how many accounts it has gone through, over one thin progress bar spanning the whole sync, never moving the title or the list; tapping it opens a sheet of the accounts, running, next or done, and the sync's last steps with their time, the app usable meanwhile and no report popping up once it ends; pulling a list down syncs that domain alone, within what the filter shows. A server that throttles is waited on for as long as it asks, within a bound so a sync never hangs, and Gmail is read below its quota rather than at it. Accounts also sync in the background while the app is not on screen, every 15 minutes by default, or 30 minutes, 1 or 2 hours, or never, as each account's settings say, and an account can notify its new mail, offered at setup.
- Added whole mailboxes: every message of every mailbox is listed (on Gmail and JMAP, what its steps bring), newest first, its sender, subject, date and marks stored in the same pass with no body, a page at a time, so the newest mail shows within seconds while the rest fills in and a sync cut off resumes where it stopped. The mail list loads lazily around where you scroll, so a mailbox of a hundred thousand messages scrolls to its oldest, and search covers every stored message, offline included. An account's settings bound its mail to the last 1, 3, 6, 12 or 24 months, by the date each message was sent; narrowing the bound frees what falls below it on the phone and nothing on the server, widening it brings the older mail back on the next sync. The paperclip is read from the message's type while listing, and corrected from its parts when you open it.
- Added a short first sync: after connecting an account, the mail tab waits for about 50 of its newest messages (its inbox alone, but on Gmail), downloaded whole so they read offline, every pass taking the inbox first after it. Older headers fill in behind, 500 messages at a time, while the app is open on Wi-Fi, the sync dock saying so meanwhile with a download glyph pulsing beside it, over a bar counting the bodies as they land; a Gmail or JMAP account is not filled, its search beyond what is on the phone being the server's own.
- Added parallel mail sync: an account's mailboxes are listed several at a time, each on its own connection (four for Microsoft 365 and JMAP, three for IMAP, two for Gmail), the inbox begun first, so every refresh and the background fill no longer wait on one mailbox after another. One mailbox failing no longer stops the others.
- Added faster calendar sync: an account's calendars sync several at a time, each on its own connection, and their events are read in a handful of requests rather than one each: twenty to a request on Microsoft 365, and none at all on Google and JMAP, whose listing already carries them. A calendar failing no longer stops the others, and an event deleted on Outlook while a sync reads it is left out rather than failing the sync.
- Added faster contact sync on Microsoft 365: contacts changed elsewhere (an import, a merge, many edited in Outlook) are read twenty to a request rather than one each, and a contact deleted on Outlook while a sync reads it is left out rather than failing the sync.
- Added band-by-band loading on Microsoft 365: older mail fetches only the messages it lacks rather than every message already stored, changes made elsewhere reach the phone whatever the age of the message, and the first sync after connecting still waits only for the newest messages.
- Added two-way phone synchronization: each addressbook mirrors into its own Android account (the DAVx5 pattern), so edits from any contacts app converge into the store and ride upstream. It is off until turned on, in the setup or an addressbook's settings, and the contacts permission is asked only then.
- Added automatic setup from an email address or a bare domain: parallel provider-rule, PACC, CardDAV, CalDAV, autoconfig and JMAP discovery over a DNS-over-HTTPS resolver, then one screen offering the domains the address serves. An address hosted at Google or Microsoft, custom domains included, is offered mail, contacts and calendars from the provider's own rules. The recommended setup is a tick per domain, none ticked to begin with, the app picking the servers and the sign-in: Google's and Microsoft's own APIs through the app's sign-in for addresses they host, elsewhere JMAP before IMAP and the DAVs, and OAuth before an API token before a password; the advanced setup lists every discovered configuration and sign-in under each switch, manual server entry included. Finishing the setup lands on the first domain the account covers, mail first, and each domain syncs under the sync dock the first time its tab is opened.
- Added authentication by password, API token or OAuth 2.0 (IMAP and SMTP over SASL XOAUTH2), with shipped Google and Microsoft clients, custom clients, and zero-registration OAuth (metadata discovery, dynamic client registration and PKCE); credentials are encrypted in the Android Keystore.
- Added a vCard 4.0 editor: a form covering every form-worthy property, the properties it does not cover kept untouched.
- Added a filter page per list: each account with a checkbox, ticked, partly ticked or not, and its collections below it with theirs, kept across restarts and applied with a button: what is unticked neither shows nor syncs, by a pull, the drawer or a background run, and a mailbox newly ticked syncs its newest mail at once. A Gmail account starts with every label but Trash and Spam, any other mail account with its inbox alone. Unticking an account folds its collections away, each keeping its own tick for when the account comes back, so two accounts' mailboxes of one name are told apart. A mailbox the server marks as the inbox, sent mail, drafts, trash, junk or archive goes by that name in your language rather than the server's own, such as Gmail's SENT or IMAP's INBOX. Mail offers role chips, Inbox, Sent, Drafts, Trash, Junk and Archive, each showing that mailbox of every shown account merged, ticked or not, without syncing anything: a pull while one is on syncs that mailbox alone, and the Sent chip also sends and shows the outbox, and *Load more* under the junk or the trash brings its older mail. A Gmail account keeps what its steps read even when archived, so it never reads a message twice; contacts and calendars offer a Default chip. An account's settings switch it on and off: one that is off syncs nothing and leaves every list and filter, its data kept. Deleting an account removes its mail and calendars with it, its contacts moving into the on-device book.
- Added Deleted items, from the drawer: every deleted message, contact and entry the phone still keeps, in one list. One whose body is stored can be restored into a collection you pick, its last one preselected, and is uploaded by the next sync; mail restores on IMAP accounts for now. Free space shows what the kept items weigh, on its button too, and removes them for good; items waiting for the server stay. Deleting messages for good warns how many of them are not on the phone and so cannot be restored, opening them or downloading the trash keeping them restorable.
- Added mail on the phone, a step at a time: the mail list shows the messages downloaded whole with their attachments, about 50 per account at first, nothing asked at setup, and *Load more* at its end brings about 50 more of each shown Gmail account, or of each shown mailbox of any other account, which then reaches further down than the others without the merged list showing days they do not hold. Once tapped it reads *Loading more* until every step ended, the dock's bar filling as each body lands. Gmail brings the messages not on the phone yet whatever their dates, so imported mail or a gap left by a failure never throws it off. An IMAP account brings its messages newest by date, so one imported message dated years back never pulls a whole mailbox in, and reads their bodies up to 50 to a request. Microsoft 365 finds them in one listing of the whole account and reads their bodies twenty to a request rather than one each. JMAP brings them in one request from where the last step stopped, each message downloaded once whatever number of mailboxes it is filed in. Mail syncs on Wi-Fi only: on mobile data the outbox still goes out, the list says it waits for Wi-Fi and syncs once Wi-Fi is back, and opening a message still downloads it. Bodies download after each sync while the app is open, newest first, in every mailbox but the junk and the trash, and a message arriving late downloads whatever its date, even after the app restarted; the junk and the trash are listed when you open one of them alone. A body that fails is tried again later in the same run, after a token renewal if it expired, and a message that keeps failing says *Download failed* rather than staying dimmed; a connection the server closed while idle (Microsoft 365 after two minutes) or that timed out is opened again and the request sent again, so it no longer leaves messages undownloaded, and an answer that came too late can no longer be stored under another message. An account's settings move the start of what is on the phone later, which frees the bodies below it after asking, their headers kept so search still finds them; a search result not on the phone is dimmed, says *Not downloaded* and downloads when opened, and opened offline says so. The unread badge counts what is on the phone, the drawer counts the bodies left, and new-mail notifications never reach below it, the messages they announce downloaded before they show. A mailbox's Download on the filter page keeps that one mailbox whole, trash included, and Stop returns it.
- Added attachments you can open and keep: tapping one in the reader opens it in the app your phone picks for it, or saves it into a folder on the phone, created on the spot if needed. A saved file is stored once however many messages carry it, and an attachment stays listed when its message is no longer on the phone, opening it then downloading the message first.
- Added a Files tab beside mail, contacts and calendars: your folders on the phone and every attachment of every account, searchable by name and sender and narrowed to images, PDFs or documents. A file opens, shares, saves into a folder, exports to the phone's storage or leads back to the message it came from; folders are created, renamed, deleted and filled from the phone's storage. Its filter page lists each account's attachments apart from your folders.
- Added links between items: every message, contact, calendar entry and file lists what it is linked to and why (an attachment, or linked by you), each opening the other. Link to searches your messages, contacts, entries and files for something to link, and Unlink removes one, warning when an automatic link may come back.
- Added automatic links: a message is linked to its sender's contact and to the event it invites to, whichever arrives first, a contact added later gathering the mail it sent, and existing mail is linked once after updating. Only real attachments are listed now, not inline images, and moving the download window later says how many messages and megabytes leave the phone.
- Added default collections: a new contact or event goes, without asking, to the collection the provider names default (JMAP, Microsoft 365, Google), else to the account's only writable one, else to the one set as default on the filter page; otherwise it asks, offering only the collections that take writes.
- Added a merged contact view with UID-based deduplication, manual link and unlink, a merge flow, a semi-automatic duplicate remover, search, vCard import and export, and a divergence flag opening a conflict-resolution form.
- Added lossless round-trips for Google People and Microsoft Graph: vCard lines with no native slot are stashed server-side and restored verbatim, and provider-only fields ride the vCard as read-only vendor properties.
- Added a next-birthday peek computed from the merged cards.
- Added the packaging: a Nix flake pinning the toolchain and a release workflow assembling one signed APK per ABI plus a universal one, and a bundle for Google Play; the APK for most phones weighs about 11 MB.
- Set the minimum supported Android version to 8.0 (API 26).
- Added English and French, French covering every screen; the app ships no other language.

### Fixed

- Fixed the connection flow finding no mail server for an address whose domain publishes only its MX records, such as one hosted at Migadu: the provider those records name is asked for its autoconfig, following the alias of its autoconfig host when that host holds no certificate for it, as Thunderbird does. The autoconfig request no longer asks for the address with its domain written twice.
- Fixed the Contacts app listing a second, empty account for an address whose calendars show on the phone: a contact saved into it never synced and was lost when the account was set up again. Calendar accounts are now of their own type, which contacts apps do not list, and those made by an earlier version move over on the next start. A phone account is no longer removed while it holds a contact created or edited in a contacts app and not yet synced, and deleting an account brings such contacts in first, removing nothing when it cannot.
- Fixed the background download starting again every few seconds, the strip saying so each time, for a message deleted from the server after the sync listed it: a message gone is now given up until its mailbox is listed again, a body that failed every attempt is no longer asked for again until then or the next start, and only Wi-Fi coming back starts the download, not every change Wi-Fi reports while it stays up.
- Fixed a downloaded message losing its body to a sync running at the same time: a sync that read the message before you opened it, or before the background download stored it, wrote it back without its body, often for new Gmail mail whose labels change right after delivery. A body is now never taken away by a sync, and one stored while another write was dropping the same bytes keeps its file.
- Fixed a mail sync failing on a message deleted from the server between the listing and the push (deleted for good, purged from the trash or the spam, or a Gmail draft saved under a new id): the change is now done, a copy of such a message is refused, and the mailbox no longer reads as one the server refused to open.
- Fixed large mailboxes slowing down as they grew: a listing page of 500 or 1000 messages read the whole mailbox to merge into, deep pages and flings read every row above them, the counts behind the list read a summary no filter asked for, and Load more sent every message the account holds to the bridge. A page now reads its own rows, so a first sync of a 30k-message mailbox and a step into a 500k-message account no longer cost what the mailbox holds.
- Fixed narrowing how many months of mail an account keeps never finishing on a large account: the collection reran itself for every message past the first 87,000.
- Fixed opening a message of 100 MB failing, and a 25 MB one taking about 120 MB of memory: a message opened from the server is now streamed into a file and filed as is, like the bodies the background download brings, and an attachment is written out without a second copy.
- Fixed the agenda freezing the screen while it rebuilds over thousands of entries: it is now built in the background, and only the entries a sync changed are expanded again.

- Fixed an IMAP message showing another message's body: a body was reused across mailboxes under the same UID, which names a different message in each. Bodies are now reused only across Gmail and JMAP labels, and the bodies wrongly reused are downloaded again after updating.
- Fixed one mailbox the server refused to open failing a whole mail sync or Load more on IMAP: a folder deleted elsewhere since the mailboxes were listed, or a Gmail label too new for the connection to see, is now skipped and the account's other mailboxes sync, the folder leaving the list at the next sync if it is gone.
- Fixed the first sync of an IMAP account whose server cannot sort (Gmail over IMAP) downloading hundreds of messages after an import: it now brings about 50 messages of the account, the newest by date across its mailboxes.
- Fixed a Gmail account's first sync stalling for a minute and a half, and later downloads pausing for a minute: two metadata requests sent side by side drew Gmail's "too many concurrent requests" refusals, each one waited out until the next minute with every other request held too. Such a refusal is now retried within a second or two, a per-minute quota a few seconds later, and Gmail is read 10 messages to a request, one request of an account at a time, paced by Gmail's quota units per account, so a first sync lands in seconds.
- Fixed opening a message waiting behind the background download of older mail or bodies: it now runs on its own, ahead of the download.
- Fixed the sync strip naming the mail while nothing was counted yet: it now says *Starting the sync* until the bar can move, and its indeterminate bar is the same size as the counting one.
- Fixed every phone sync of an address book leaving a database connection open behind it: the whole app now shares one store.
- Fixed the app not working on Android 8 to 13: its store needs SQLite 3.37 or newer, which Android ships only from Android 14, so it could not be created on older phones. The app now bundles SQLite 3.49 and uses it on every Android version it supports, at the cost of about 1.9 MB per APK.
- Fixed the agenda listing everything from today on, months ahead, while it showed this week: with no day picked, this week now lists its own seven days, from the locale's first weekday, past days included, like every other week.
- Fixed a message with no date vanishing from the phone when older mail was loaded: a band of older mail is listed by date, which never returns an undated message, so its absence there no longer reads as a deletion.
- Fixed older mail never loading on Microsoft 365 and JMAP accounts, the background fill stopping at once: the connection opened to load it did not know the mailboxes yet.
- Fixed the merged mail list slowing down as the store grew: a page over several mailboxes sorted every stored message of them before showing fifty, and now walks one index kept in that order, so a page of a fifty-thousand-message store reads in a fraction of a millisecond. An existing store gains the index the next time the app opens it.
- Fixed a contact or calendar entry created on the phone coming back after being deleted, on Google and on CardDAV and CalDAV servers: the app kept a created card under a name no server held, kept no revision where Google's CalDAV answers none, and kept Google Calendar's revision of an edited event garbled, so the delete never reached the server or lost to the next sync. A contact Google rewrote also no longer loses an edit made on the phone when it changes elsewhere.
- Fixed a message nesting thousands of parts, or a calendar entry nesting thousands of components, crashing the app every time a sync reached it; such a message is now read from its header, such an entry refused. A message whose reading still crashes the app is given up after three tries, its row saying *Download failed*, rather than crashing every sync.
- Fixed an event repeating every second or minute, or with a huge count, holding the agenda or an edit for minutes, and a Microsoft 365 series spanning centuries reading its exceptions in hundreds of requests: a series is walked a bounded number of steps, and read within five years of today.
- Fixed the app failing on every start after a transfer to a new phone: the accounts, sealed with a key that never leaves the old phone, are dropped once and you are asked to add them again.
- Fixed a long attachment name in Chinese or Japanese failing to open.
- Fixed a message being delivered twice when the connection died after it was handed over: the app can no longer tell whether the server took it, so it shows *May have been sent* and waits for you to tap *Send again* rather than sending it on its own. A sign-out failing after the server accepted a message no longer sends it again either.
- Fixed a second copy of a message appearing when a move on a server without MOVE, or the copy kept in Sent, was carried out again after a lost answer: the app now looks for the message in the target first.
- Fixed a Microsoft 365 event created on the phone being created twice, its attendees invited twice, when the answer to its creation was lost.
- Fixed a slow server write being sent again after 30 seconds without an answer, and a send or other non-repeatable request being repeated after a 503.
- Fixed a JMAP account whose sign-in expired during a mail download marking every message it was downloading as failed: the download now stops for the sign-in to be renewed, then carries on.
- Fixed one mail account's sync and background download reaching into another account's mailboxes when several are connected: each account now syncs and downloads its own mailboxes alone.
- Fixed a custom OAuth client signing in through a `http://127.0.0.1` redirect failing on servers that require the RFC 8707 resource, such as Fastmail: the resource is now asked for as on the app's own redirect.

### Security

- Encrypted the pending sign-in a browser step leaves on the phone, its PKCE verifier and a custom client's secret included, like the accounts, and removed it as soon as the sign-in completes, fails or is abandoned; one an older version left unencrypted is wiped on the next start.
- Refused to send a password or token over an unencrypted connection, whatever asked for it: plain `imap://` and `http://` servers are refused when typed or discovered, a non-TLS CalDAV or CardDAV SRV record is ignored, and the bridge and the transport both refuse any credential on a plain socket (SMTP only after STARTTLS).
- Bounded redirects: at most five, never from https to http, and never with the credential to another server; a JMAP download served from a CDN is followed without the token, and a principal or home set a DAV server names on another site is refused.
- Used the app's own Google and Microsoft sign-ins only when every server of the account is that provider's own, with their fixed scopes; any other configuration naming their sign-in gets a generic one.
- Checked OAuth servers: https only for the issuer, its metadata endpoints and the authorization page the browser opens, the metadata's issuer must be the one asked for (RFC 8414), and a sign-in coming back from another issuer is refused (RFC 9207). A failed sign-in no longer logs or shows the redirect, which carries the one-time code.
- Showed where a password goes before it does: each sign-in card names the scheme and host it signs in to, flagged when it is outside the address's domain.
- Ignored an `http` autoconfig URL published in a `mailconf=` TXT record.
- Renewed an OAuth credential once when several sync workers find it expired together, the others reusing that renewal, so a provider rotating refresh tokens no longer signs the account out.
- Opened a link in a message only when you tap it, and only a web or mail link: a message can no longer open a page on its own when read (a read receipt through a refresh) or start another app through a frame.
- Kept the store and the accounts out of cloud backups and device transfers.
- Made the contacts and calendar sync adapters ignore another app asking them to sync an account or kind of data that is not theirs, which on Android 8 to 10 could crash the app or turn a book's contacts sync off.
- Bounded what a server's calendar puts in the phone's calendars: at most 5 reminders an event, long texts cut, and an event repeating every second or minute listed rather than expanded by the phone.
- Removed messages and imported documents a stopped sync or import left in the cache, and dropped the invisible characters that let an attachment name hide its real extension.
- Kept debug records out of a release build's logs, and the addresses and links logged before.
- Kept another app, or a link in a message, from cancelling a sign-in in progress: only the sign-in's own redirect, carrying its state, ends it. A sign-in left in the browser is forgotten after 15 minutes, and a custom client's sign-in shows its loader.
- Hardened a custom client's local sign-in redirect: it waits on its own thread, ignores local connections that send nothing or something else, and accepts only `http://127.0.0.1`.
