# The bridge takes the released libraries

Every Pimalaya dependency of rust/Cargo.toml moves to its latest crates.io release: ical-rs 0.7, io-gcal 0.3, io-gmail 0.6, io-gpeople 0.6, io-http 0.6, io-imap 0.8, io-jmap 0.7, io-msgraph 0.7, io-oauth 0.5, io-pim-discovery 0.11, io-pimdir 0.9, io-smtp 0.7, io-webdav 0.6 and vcard-rs 0.6. The git `[patch.crates-io]` pins go, and no git source is left in rust/Cargo.lock. `rust-version` is 1.89, io-pimdir's own. The devshell moves to nixos-26.05 and JDK 21.

- **mail-parser is gone; the reader parses with mime-rs** (mail). The reader (`parse`, `describe`, `write_part` in rust/src/mail/read.rs), the envelope and subject reads of rust/src/mail/compose.rs, `mail::message_id` and the depth count behind `mail::derivable` read the message through mime-rs's `MimeCst`, the parser io-pimdir already runs, so the bridge carries one MIME parser. mail-parser 1.0 would have raised the floor to Rust 1.98 and brought a third base64 codec. What the reader shows is unchanged on the corpus (MailClientTest), but for three edges where mime-rs reads what is there: a multipart cut off before its close shows the text part that arrived, where mail-parser showed nothing; bytes opening on `FF FE` read as UTF-16LE text, the byte order mark honoured; and a UTC date reads `+00:00` where it read `Z`, both of which `MailDate` parses. An empty input is still refused, now by the bridge itself (`read::parse` and `read::write_part`), as mime-rs reads any bytes as a message. A part stating no `Content-Type` still lists with no media type, read from the field rather than the `text/plain` RFC 2045 section 5.2 defaults it to.
- **The bridge tags its own IMAP commands.** io-imap 0.8 asks for each command's tag (`WantsTag`); `ImapState` numbers them `P1`, `P2`, on its connection, rather than taking io-imap's `client` feature for its `TagGenerator`, which brings the std client with it. A QRESYNC `VANISHED (EARLIER)` now arrives as UID ranges, expanded to the UIDs the delta lists.
- **A vCard line the app writes folds at 75 octets** (contacts). vcard-rs 0.6 folds an edited or built 3.0 or 4.0 line longer than 75 octets, as RFC 6350 section 3.2 asks, and leaves an unedited line as it was, so a stored card keeps its bytes and its hash. contact-form.txt and mapping-corpus.txt take the new outcomes: the one folded `NOTE` line, and the 27 merge and apply outputs carrying a long note.
- **io-oauth 0.5 carries the RFC 8707 resource** in `Oauth20AuthRequestParams` and `Oauth20AccessTokenRequestParams`. The bridge leaves it empty: the resource still travels as an extra, which replaces it.
- **The io-pimdir spec vectors come from a checkout.** The published io-pimdir leaves spec/vectors and spec/payloads out of its package, so the tests running them (rust/src/offline.rs `io_pimdir_spec_dir`, search/tests.rs, PimdirVectors.java) read `PIMALAYA_IO_PIMDIR_SPEC` first, then the source rust/Cargo.lock locks, a git checkout or a registry package. CI clones io-pimdir at the tag of the locked version and sets the variable (.github/workflows/tests.yml).
- **Java 21 for the unit tests.** Under nixos-26.05 Gradle runs on `JAVA_HOME`, which named JDK 17, and Robolectric runs SDK 36 on Java 21 only; the devshell takes JDK 21, the bytecode still targeting 17.
- **The SIMD codecs get the detected CPU.** `JNI_OnLoad` installs simd-cpu's detected token (`SimdCpu::install_detected`) beside the logger, for the base64 and quoted-printable codecs mime-rs, ical-rs and vcard-rs decode with. It matters on the x86 ABIs alone (emulators, Chromebooks), whose SSSE3, AVX2 and AVX-512 backends run only once detected: NEON is the aarch64 baseline, and the codecs carry no 32-bit ARM backend.

`cargo clippy --all-targets -- -D warnings` clean; `cargo test` 605 passed with `PIMALAYA_IO_PIMDIR_SPEC` on io-pimdir v0.9.0's spec/; `:app:assembleDebug` and `:app:testDebugUnitTest` green.
