# The store follows pimdir draft-10

The app follows pimdir storage-draft-10, sync-draft-10 and search-draft-10 (ae8b231) on io-pimdir 0.11.0 from crates.io, the git patch gone. A store an earlier build wrote is refused (`store-version`), as every draft's is, and the app opens on its reinstall screen; an index of the earlier draft is rebuilt.

- **Statements.** The forks of `evict_before` (the renamed `collect_before`, which now keeps an item a delivered create binds), `release_before`, `release_bases_before`, `purge_retained_before`, `bump_next_seq` and `init_index_meta` were read again from the canonical text and name its digest; `retry_action` is a new fork (`RETURNING`). The app's own `in_reply_to_of` and `item_in_reply_to` read `message_id`. Java binds `:before` (MailStore, DeletedItems) and `:message_id` (PimdirSummary).
- **The binding guard.** `PimdirSql.bind` refuses a call naming a value its statement does not take while leaving one of its parameters unnamed, the shape of a renamed parameter. Chosen on a measurement over the JVM suite (a temporary audit in `bind`, removed): 42 call shapes leave a parameter unnamed (optional summary columns, open cursors) and 10 name a value their statement does not take (one map serving several statements), each on purpose, and none does both. Refusing a parameter left unnamed, the first proposal, would have broken those 42. The guard does not see a parameter the standard added (`seq_for_link_any`'s three).
- **Identity** (ledger line A1 of pimdir's audit). `seq_for_link_any` is bound with the subject, date and sender of the summary being written, a create made from another message with its origin's; the lookups (`held_object`, `held_message_object`) answer every holder with those three, the Java agreement test gone, the engine's standing; a mail upsert naming a row that holds another message is keyed apart (`names_another_message`, minted `dup:<key>#<handle>`); an item a batch retired and its account holds elsewhere is purged when the batch ends (`held_elsewhere`, `retained_item`, `purge_item`).
- **Mutations.** `Mutation.remove` carries `ifMatch` and `resolves`, `Mutation.setFlags` a `base`. A calendar removal over the body its page read is the engine's `if_match` now (CalendarStager), and the conflict form's delete names the versions it showed (EventWrites). A marker toggled on a message states the set it was read from, a set nobody read being replaced whole as before (MailStager). The tombstone that settles no conflict by itself came with the crate, the Java upsert asking its hub.
- **Queue.** A submission whose outcome is unknown is parked under `unconfirmed: ` (io-pimdir's constant, over the bridge), where the app wrote `uncertain: `; a refusal whose text begins so is recorded behind `failed: `; *Send again* runs `retry_action`, the row, its id and its attempts kept; a payload is judged by `codec::payload_outcome`, an unknown one skipped. Without this last change a `submit` at `v` 2 would have been handed over as `v` 1, io-pimdir 0.11 keeping an unknown payload where it answered an error.
- **Index.** `index_meta.extraction` and `extractor` (`pimalaya-android 1, io-pimdir 1`), an index recording another of either rebuilt; the index `object_not_ok`; `hit` in place of io-pimdir's `LOAD_HIT_PLACEMENTS`; a parenthesised group compiled as its operand; a date bound no four-digit year states read as open, which two of the new search vectors failed on.
- **Blob store.** objects/ is flushed when a write creates a shard, the shard when a held name is kept and after the collector's unlinks; the temporaries a killed writer left are unlinked once per process, off the main thread, those a writer of the process is still to move left.
- **Conformance**: `storage-draft-10 owner (own statement text), sync-draft-10 engine`.

Tests. New, each failing on the earlier code: `aRenamedParameterIsRefusedWhereItIsBound` (the earlier `bind` threw nothing), `aMessageSharesItsPublicIdOnlyWithARowThatAgrees`, `aMemberNamingAnotherMessageIsKeyedApart`, `anItemRetiredWhileHeldElsewhereIsPurged`, `aBodilessItemIsPurgedOnlyForAHolderThatAgrees` (the earlier write joined, shared and retained without a test of the summary, pimdir's audit having replayed the first on a scratch database), `aRowRevivedByItsBatchIsNotPurged` (holds the batch-end settling), `aRemovalAndAFlagChangeStateWhatTheyWereDecidedOver` and `aMarkerStagedFromItsBaseKeepsWhatLandedSince` (no such members before), `aConflictedEntryDeletedNamingNoConflictIsRefused` (the earlier engine deleted, which the test beside it asserted), `aResentSubmissionKeepsItsRowAndItsPlace` (the earlier resend appended a row), `aRefusalNeverReadsAsAnUnknownOutcome`, `aKilledWritersTemporariesAreUnlinked`; in Rust `a_bound_no_four_digit_year_states_is_open`, the three payload outcomes over payloads.json `v` 2, the search vectors at queries.json `v` 4 over store.json `v` 2 (208 cases run, 4 not binding the shape), the held check over both revisions, `retry_action` beside its canonical text. Those were written against the new code and reasoned against the old, not each run on it. Fixtures restated: stamps with milliseconds (the new `CHECK`s), draft names, and DeletedItemsTest's two restores, whose bodies now state the sender and date their summaries do, a restore reviving a row only when the two agree.

Checked: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test` (655 passed, 1 ignored, `PIMALAYA_IO_PIMDIR_SPEC` at io-pimdir's spec/), `:app:assembleDebug`, `:app:testDebugUnitTest` (1,014 tests, 5 skipped) and `:client:testDebugUnitTest` (14), offline, on the host. Nothing was installed nor run on a device, and no account was reached.

Left, and for the owner:

- A delete of a conflicted contact, task or message from a list or an ordinary page is now refused by the engine (`conflict-unresolved`) and reaches the caller as a `PimalayaException`: ContactsList, ContactWriter, ContactEditor, TaskWrites and MailStager state no `resolves`, no conflict being shown there. What those screens say, and whether the contacts list's own conflict rows count as shown, is undecided; nothing catches the refusal today.
- The temporaries sweep runs at process start. The standard leaves the collector's schedule to the owner, and the app's collector walks no directory, so the orphan walk of STORAGE §5 step 3 stays unbuilt.
- A search asked in another zone than its index's (`index_zone`, 2 vector cases) is not bound: the app asks every query in the zone its index states.
- A restore from Deleted items into the item's own mailbox revives its row only when the stored summary agrees with the body; a row listed from an envelope decoded otherwise is restored as a second row.
- The mint rule reads the row as the batch finds it, op by op, where io-pimdir reads the state before the batch.
- `PimdirLoaded::offered` is carried by the wire and filled by no load: only the `Disagreed` event reads it, which no screen shows.
- Not started, as scoped: ledger lines A2, A3, A5, A6, A7, the locks and receipts of A4, coverage, an in-app erase.

Capabilities moved: offline-store (the draft, the binding guard, identity, the purge, the lookup, the flag base, the queue, the index, the blob store), mail (A send that may have gone waits for the user), conflicts (A removal names the conflicts it settles).
